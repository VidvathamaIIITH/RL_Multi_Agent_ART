\newcommand{\PAPERTITLE}{CanvasMind\,--\,Quad: A Configurable Four-Agent
  Sequential Pipeline for Legible Additive Co-Creation on a Shared Canvas}
\newcommand{\PAPERAUTHOR}{Vidvathama Ramesh \\ RL\_Multi\_Agent Project, TCS Research}

\newcommand{\ABSTRACTTEXT}{%
We present \textbf{CanvasMind\,--\,Quad}, the four-agent variant of the CanvasMind
co-creation system. Four \emph{independently configured} agents paint one
\emph{shared canvas} in \textbf{strict sequence}---agent $1 \to 2 \to 3 \to 4$
per round, each adding exactly one new object on top of the previous image, so a
painting of $4R$ visible steps grows for $R$ rounds. Each agent is configured
along two orthogonal axes: an \emph{artistic voice} (one of six painterly presets,
or a free-text override) that sets how it paints, and a \emph{persona identity}
(one of eight seed-memory characters after \citet{park2023generative}) that sets
who it is; a lightweight deterministic retriever, \RAG{}, injects precise stylistic
keywords when it recognises an art movement in the brief or voice. A fifth agent,
\JUDGE{}, scores the sequential collaboration across five axes and a composite but
never edits the canvas. Deliberately, the Quad pipeline carries \textbf{no
reinforcement-learning layer}---no reward model, best-of-$N$, bandit, memory
stream, or credit assignment; those live in the two-agent companion system and
are the subject of a separate paper. This keeps Quad a clean, legible substrate
for \emph{configurable} multi-voice co-creation: the whole run is one Python file
serving the browser and the API on a single port over Server-Sent Events, calling
Azure OpenAI over raw REST, and every session is persisted in full for audit. We
describe the architecture, the agent configuration, the additive image pipeline,
the storage format, and how Quad relates to its RL-bearing companion. We are
explicit that no live-model evaluation or human study is reported here; the system,
its storage, and a reproducible offline harness are released as code.%
}

\section{Introduction}
% =============================================================================
Prompt-to-image tools collapse creation into one call and hide the reasoning that
produced the picture. CanvasMind makes that reasoning visible by turning creation
into a turn-based collaboration on a \emph{single shared canvas} that is handed
from agent to agent, each adding exactly one object. This paper describes the
\textbf{four-agent} member of the family: a configurable pipeline in which four
distinct painters act in a fixed order, so a viewer can watch a composition
assemble one deliberate element at a time and can read each contributor's hand.

The design goal for Quad is \emph{configurability with legibility}. Each of the
four agents is set independently along two axes that we keep orthogonal on
purpose: an \emph{artistic voice}---how it paints (six painterly presets, or a
free-text description that overrides them)---and a \emph{persona identity}---who
it is (one of eight seed-memory characters spanning walks of life, after
\citealp{park2023generative}). A curator can therefore stage, say, a Baroque
traditionalist voiced by a retired shipwright followed by a neon cyberpunk voiced
by an astronomer, and see how the two sensibilities negotiate one surface. A
deterministic keyword router, \RAG{}, sharpens each agent's prompt with precise
stylistic vocabulary when it recognises a movement. A fifth agent, \JUDGE{},
assesses how well the four built on one another and presents the accumulated
canvas; it never lifts a brush.

Quad deliberately omits the inference-time reinforcement-learning machinery
(reward model, best-of-$N$ search, bandit-driven strategy selection, memory and
credit assignment) that the two-agent companion system carries. That machinery,
and a formal audit of it, are the subject of a separate paper; here the point is
the opposite---a minimal, transparent, configurable substrate whose behaviour is
fully determined by each agent's declared voice, persona, and the strict turn
order. The clean separation also makes Quad a natural \emph{architectural control}
for studying what the RL layer adds.

\paragraph{Contributions.}
\begin{enumerate}[leftmargin=1.3em,itemsep=1pt,topsep=2pt]
\item \textbf{A configurable four-agent sequential co-creation pipeline}
      (\S\ref{sec:overview}--\S\ref{sec:pipeline}) with orthogonal voice/persona
      configuration and an explicit ``what I see / what I add'' JSON contract.
\item \textbf{A deterministic art-history retriever} (\S\ref{sec:rag}) that
      enriches prompts with movement-specific vocabulary, with a retriever-shaped
      interface so it can later be swapped for a vector store.
\item \textbf{A single-file, one-port runtime} (\S\ref{sec:impl}) that streams
      every step to the browser and \textbf{persists every session in full}
      (\S\ref{sec:storage}) for audit and later study.
\item \textbf{An explicit positioning} (\S\ref{sec:relation}) against the
      RL-bearing two-agent companion, making the architectural difference precise.
\end{enumerate}

\paragraph{Scope and honesty.}
This paper describes a system. It reports \emph{no} live-model quality numbers and
\emph{no} human study: Azure OpenAI credentials are required to run it, and a user
study is future work. \S\ref{sec:human} specifies the instrumentation---already
implemented---that a study would use.

\section{Related Work}
% =============================================================================
\paragraph{Multi-agent LLM systems.}
Frameworks that coordinate several language-model agents
\citep{li2023camel,hong2024metagpt,wu2024autogen,du2024debate} typically pursue a
\emph{shared} task through discussion or role play. Quad differs in medium and
mechanism: the agents act on a shared \emph{image} through a strict additive turn
order rather than a conversation, and each is configured independently rather than
assigned a functional role.

\paragraph{Generative-agent personas.}
Persona identities use the seed-memory schema of \citet{park2023generative}
(\code{innate}, \code{learned}, \code{currently}, \code{lifestyle},
\code{living\_area}), which pairs a character sketch with lightweight cognitive
parameters. Quad uses the identity to colour \emph{what} an agent proposes; it
does not run the full memory-stream/reflection machinery of that work (the
companion two-agent system does).

\paragraph{Human--AI co-creation.}
The interaction design follows co-creative agents that draw or paint alongside a
person \citep{davis2016empirically,oh2018lead,karimi2020creative}, and the
motivation---making machine creative \emph{process} visible, not only its
output---follows \citet{epstein2023art} and \citet{doshi2024generative}. Framing
of machine creativity follows \citet{boden2004creative},
\citet{colton2012computational} and \citet{ritchie2007some}.

\paragraph{Retrieval.}
\RAG{} is a deliberately minimal retriever \citep{lewis2020retrieval}: a keyword
router over a small curated knowledge base, shaped so a true embedding store can
replace it without changing callers.

\paragraph{Instruction-guided image editing.}
The additive canvas relies on editing that preserves prior content
\citep{meng2022sdedit,hertz2023prompt,brooks2023instructpix2pix}, implemented via a
hosted \code{images/edits} endpoint \citep{microsoft2025azure} rather than a local
diffusion model \citep{rombach2022high}. Events stream to the browser over
Server-Sent Events \citep{whatwg2024sse}.

\section{System Overview}
\label{sec:overview}
% =============================================================================
A session has three phases. \textbf{(1) Configuration \& briefing:} the operator
sets each of the four agents (name, voice, optional custom prompt, persona
identity), a shared brief and style (typed or invented by the model), and the
number of rounds $R\in[1,6]$. \textbf{(2) Sequential collaboration:} for each
round, agents $1\to 2\to 3\to 4$ act in order; each reads the current canvas, adds
one new object, and the object is composited onto the shared image. \textbf{(3)
Critique:} \JUDGE{} scores the collaboration and the accumulated canvas is
presented. Every event is streamed live; a \emph{Stop} control ends the turns
early, after which \JUDGE{} evaluates the work so far.

\section{Configuring the Four Agents}
\label{sec:agents}
% =============================================================================
Each agent is set along two orthogonal axes plus a name.

\emph{Configure Custom Agent} prompt that overrides the preset entirely. The voice
sets palette, mark-making, and subject sensibility, and is echoed into the image
prompt so the rendered addition matches it.

\paragraph{The turn contract.}
On its turn an agent receives the shared brief, style, any \RAG{} keywords, and the
recent collaboration transcript, and must reply in strict JSON: \code{sender},
\code{sees\_on\_canvas} (what is already painted), \code{new\_object} (the single
element it adds), \code{where}, \code{palette}, \code{reasoning}, and
\code{confidence\_score}. Naming \code{sees\_on\_canvas} keeps the chain legible:
each agent states what it is building on before it adds. Parsing is
fence-tolerant with a fallback, so a single malformed reply never aborts a run.

% =============================================================================
\section{ArtHistoryRAG}
\label{sec:rag}
% =============================================================================
\RAG{} is a lean, deterministic context router---no external vector store. It
holds a curated $16$-entry knowledge base mapping a movement or technique
(e.g.\ \emph{chiaroscuro}, \emph{cyberpunk}, \emph{ukiyo-e}, \emph{brutalism}) to a
short phrase of precise stylistic vocabulary. On each turn it scans the brief,
the agent's voice and keywords, and injects up to three matching phrases into the
prompt, sharpening the rendered result toward the intended movement. Because its
interface mirrors a retriever (\code{enrich(text, max\_hits)} / \code{retrieve}),
it can be replaced by an embedding vector store \citep{lewis2020retrieval} without
touching the agents.

\section{The Sequential Pipeline}
\label{sec:pipeline}
% =============================================================================
The orchestrator (\code{QuadSession}) runs a strict nested loop: for each round
$r=1\dots R$, for each agent index $0\dots 3$, the agent takes its turn and its
one new object is composited onto the shared canvas (Figure~\ref{fig:quad}). The
first turn of the session generates the opening element on a blank canvas; every
later turn \emph{edits} the current canvas to add exactly one object while
preserving all prior content. With $R$ rounds this yields $4R$ displayed step
images (one generation followed by $4R-1$ additive edits), then \JUDGE{}.

\paragraph{The additive image pipeline.}
Two Azure image operations are used. \textbf{Generation} (\code{images/generations})
creates the first object on a blank canvas. \textbf{Editing} (\code{images/edits})
adds every later object: the current canvas is uploaded as multipart form-data with
an emphatic instruction to keep all existing content exactly as it is and add only
the one new element, rendered in the acting agent's image style. Both return base64
PNG, inlined as \code{data:} URLs and written to disk. Every image step is wrapped
in try/except: a failed edit emits a warning, keeps the previous canvas, and
continues; with no image deployment at all, the four agents still hold the full
textual chain.

\paragraph{\JUDGE{}.}
When the sequence finishes (or is stopped early), \JUDGE{} scores the
\emph{sequential collaboration} on five axes---compositional coherence, style
fidelity, emotional resonance, originality, and collaboration quality---plus a
composite, with reasoning, highlights, and a one-sentence summary
(Table~\ref{tab:judge}). It makes no edit; the final image is the accumulated
canvas itself.

\section{Per-Session Storage}
\label{sec:storage}
% =============================================================================
Every session opens a numbered directory and records the run in full, so a
session is a self-contained, auditable artefact. Under
\file{data/sessions/session\_$\langle N\rangle$/} the app writes a
\file{session.json} manifest (configuration, the four agents' voices and persona
ids, deployments, timings, outcome); a \file{json/} tree with an ordered
\file{events.jsonl}, an \file{llm\_calls.jsonl} logging every prompt, raw response
and latency, a per-turn record (the chosen object, placement, palette, the agent's
reasoning and its timestamp, and any \RAG{} keywords), the critic evaluation, and a
summary; and an \file{images/} folder with every step PNG and the final canvas. A
thread-local recorder lets the Azure wrappers log themselves, so capture requires
no change at the call sites; recording is wrapped so a storage error can never
abort a run. A pre-session participant form and a post-session experience survey
are written into the same directory when a study is run (\S\ref{sec:human}).

\section{Implementation}
\label{sec:impl}
% =============================================================================
The runtime is a single Python file, \file{canvasmind\_app.py}, serving the UI and
the API on one port. The browser loads one page from the same origin and fetches
relative \code{api/...} paths, so a reverse-proxy sub-path prefix is preserved---no
CORS, no second port. Azure is called over raw REST with
\code{max\_completion\_tokens} and no custom temperature, as the \code{gpt-5.2}
deployment requires \citep{microsoft2025azure}. A background thread per session
pushes events onto a queue that the SSE endpoint drains; thirteen event types are
defined (\code{session}, \code{turn}, \code{agent}, \code{image\_pending},
\code{image}, \code{critic}, \code{final}, \code{summary}, \code{warning},
\code{error}, \code{done}, and---shared with the companion system---\code{metrics}
and \code{reflection}, unused here). The four-panel UI streams each agent's feed,
a labelled filmstrip, a click-to-expand full brief, and per-turn cards whose
reasoning, palette and placement expand on click.

\paragraph{Compute budget.}
Each quad turn is two model calls: one chat completion for the agent's decision and
one image call (generate or edit). At the end, \JUDGE{} is one more chat call. A
session with $R$ rounds therefore costs $8R + 1$ model calls and produces $4R$
step images. There is no reward model, probe, bandit, or credit computation to pay
for---by design.

\section{Relation to the Two-Agent Companion}
\label{sec:relation}
% =============================================================================
Quad shares the additive shared-canvas protocol, the \JUDGE{} critic, the
single-file transport, the eight persona identities, and the storage format with
the two-agent (\textsc{Aria}/\textsc{Nexus}) companion system. It differs in
exactly one dimension: the companion wraps its two agents in an
\emph{inference-time reinforcement-learning layer}---a reward model scoring five
aesthetic dimensions, best-of-$N$ candidate selection, a per-agent bandit over
artistic strategies, a memory stream with reflection, and Shapley/empowerment/%
Goodhart diagnostics---whereas Quad has none of these (Table~\ref{tab:vs}). The
companion is also more parallel (two agents alternating) where Quad is strictly
sequential over four. This makes Quad a clean architectural control: the
difference between the systems is precisely the RL layer plus the memory
substrate. The companion system, and a formal audit and repair of its RL layer,
are the subject of a separate paper.

\section{Toward a Human Study}
\label{sec:human}
% =============================================================================
No human evaluation is reported. The instrumentation for one is implemented and
specified here so a study would be pre-registered rather than reverse-engineered.
Before the interface loads, a participant form collects age, gender, and self-rated
art expertise. After a session, a survey of at least ten items---six on a $1$--$10$
numeric scale (e.g.\ ``how coherent did the four agents' additions feel
together?'') and six five-point Likert items \citep{likert1932technique} on
ownership, surprise, perceived collaboration and trust, complemented by the
Creativity Support Index \citep{cherry2014quantifying}---is recorded into the
session directory. Final canvases can be rated blind by independent judges via the
Consensual Assessment Technique \citep{amabile1982social}, yielding a human
composite to compare against \JUDGE{}'s. A natural first study contrasts the
configurable Quad pipeline against the RL-bearing companion on the same briefs.

% =============================================================================
\section{Conclusion}
% =============================================================================
CanvasMind\,--\,Quad turns image-making into a legible, configurable, four-way
sequence on one shared canvas: each of four agents is set independently by voice
and by persona, acts in a fixed order, and adds a single, readable element, while a
critic scores the chain and presents the whole. By deliberately omitting the
reinforcement-learning machinery of its two-agent companion, Quad stays a
transparent substrate whose output is fully determined by how it is configured---
and, for that same reason, a clean control against which the value of that
machinery can later be measured. The system, its full-fidelity per-session storage,
and a reproducible offline harness are released as code; a live-model and human
evaluation is the natural next step.

% =============================================================================
\section*{Ethics Statement}
% =============================================================================
The system generates images with a hosted model and inherits its training-data
provenance, biases and content-policy behaviour; we make no claim to originality of
the underlying generative process. The eight persona identities are fictional
composites, not real individuals, designed to span occupations and ages rather
than to stereotype: a persona shapes the objects an agent proposes and nothing
else. Because a persona conditions an artistic voice, deploying the system with
personas keyed to protected attributes would risk essentialising them, and we do
not do so. Any human study following \S\ref{sec:human} requires informed consent,
the right to withdraw, and storage of survey responses separated from identifying
information; the per-session records contain participant-authored prompts and must
be treated as personal data.
